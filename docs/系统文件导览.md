# CapitalPay — 文件导览

本文档帮助你快速理解项目结构，并定位「想改某个页面/功能时应该打开哪个文件」。

### 角色与余额

对外统一称 **Agent / Customer / Bank**（代码标识不变：`agent` / `customer` / `bank` 等）。余额只认 **系统账面**，不查银行实金。

| 对外 | 职责 | 代码/模块线索 |
| --- | --- | --- |
| **Agent** | 代客操作（不是收款方） | `apps/agent`、门户 `:1026` |
| **Customer** | 资金所有人；指定收款账户 | `apps/merchant` / `user_portal`、门户 `:1027` |
| **Bank** | 资金通道（本阶段 Mock） | `apps/param`、`apps/routing`、运营 Banking |
| **CapitalPay** | 平台记账 / 审核 / 付出 | 本仓库后端 `apps/*` + 运营后台 `:1025` |

## 1. 五分钟读懂架构

系统采用 **前后端分离**：

```
┌─────────────────────────────────────────────────────────┐
│  frontend/client_portal   (:1025)  运营后台              │
│  frontend/customer_portal (:1026 Agent / :1027 Customer) │
│         │ Vue 3 + Element Plus + Vue Router              │
└─────────┼───────────────────────────────────────────────┘
          │ HTTP  /api/v1/*
┌─────────▼───────────────────────────────────────────────┐
│  Django REST API  (:1024)                                 │
│  apps/*  各业务模块（models / services / views）          │
└─────────┼───────────────────────────────────────────────┘
          │
     本地 db.sqlite3（或 MYSQL_*）/ 生产 MySQL 8.0 · media/
```


| 你想做什么       | 去哪里找                                                        |
| ----------- | ----------------------------------------------------------- |
| 改页面文字、布局、按钮 | `frontend/*/src/views/*.vue` 或 `frontend/*/src/i18n/*.js`   |
| 改接口请求地址     | `frontend/*/src/api/*.js`                                   |
| 改业务逻辑、保存数据  | `apps/<模块>/services.py`、`views.py`、`models.py`              |
| 改路由/菜单      | `frontend/*/src/router/index.js`、`layout/DefaultLayout.vue` |
| 改 API 路径挂载  | `b2b_payment/urls.py`、各 app 的 `urls.py`                     |

## 2. 顶层目录说明

```
CapitalPay/
├── b2b_payment/          # Django 项目配置（settings、根 urls、wsgi）
├── apps/                 # 16 个业务模块（后端全部逻辑在这里）
├── frontend/
│   ├── client_portal/    # 运营后台 Vue 应用（:1025）
│   └── customer_portal/  # 客户/代理门户 Vue 应用（Agent :1026，Customer :1027）

├── media/                # 用户上传文件（证件照等，本地开发用）
├── reconciliation_files/ # 对账测试用 mock CSV
├── manage.py             # Django CLI
├── requirements.txt      # Python 依赖
└── .env.example          # 环境变量模板
```

## 3. 后端模块速查表

每个 Django App 通常包含：`models.py`（数据表）、`services.py`（业务逻辑）、`views.py`（API 视图）、`serializers.py`（请求/响应格式）、`urls.py`（路由）。


| 模块               | 业务职责                      | 关键文件                                                                        |
| ---------------- | ------------------------- | --------------------------------------------------------------------------- |
| `core`           | 基础层、仪表盘、定时任务、种子数据         | `views.py`、`management/commands/run_scheduled_jobs.py`、`seed_data.py`       |
| `merchant`       | 商户管理、KYC、生命周期             | `models.py`、`services.py`、`views.py`                                        |
| `payment`        | 支付订单、退款、汇款、收银台、银行网关       | `models.py`、`services/payment.py`、`views.py`、`views_cashier.py`             |
| `account`        | Nostro 账户、虚拟账户、入金、拨付、资金流水 | `models.py`、`services.py`、`money_movements.py`                              |
| `reconciliation` | 对账引擎（拉单、比对、差异处理）          | `engine/`、`tasks.py`、`views.py`                                             |
| `settlement`     | 清算批次、手续费分润                | `engine/`、`models.py`、`views.py`                                            |
| `openapi`        | 商户 HMAC 签名 OpenAPI 鉴权     | `authentication.py`、`urls.py`                                               |
| `report`         | 报表、经营指标                   | `analytics.py`、`metrics.py`、`views.py`                                      |
| `rbac`           | 运营用户、角色、权限、操作日志           | `permissions.py`、`services.py`、`views.py`                                   |
| `user_portal`    | **终端用户注册/登录/Onboarding**  | `models.py`（`UserOnboarding`）、`services.py`（`submit_onboarding`）、`views.py` |
| `agent`          | 代理商、分润、PRN                | `models.py`、`services.py`                                                   |
| `compliance`     | 制裁名单扫描                    | `services.py`、`views.py`                                                    |
| `routing`        | 银行通道路由                    | `services.py`、`views.py`                                                    |
| `param`          | 系统参数（合作银行等）               | `services.py`、`views.py`                                                    |
| `adjustment`     | 调账申请                      | `services.py`、`views.py`                                                    |
| `exchange`       | 汇率                        | `providers.py`、`views.py`                                                   |




### API 前缀


| 前缀                 | 调用方           | 鉴权      |
| ------------------ | ------------- | ------- |
| `/api/v1/`         | 商户/代理 OpenAPI | HMAC 签名 |
| `/api/v1/admin/`   | 运营后台          | JWT     |

## 4. 前端页面 → 文件对照表

```
views/SomePage.vue     ← 页面 UI 和交互逻辑
api/someModule.js      ← 调用后端的 HTTP 请求
router/index.js        ← 路由注册（URL → 页面）
i18n/en-US.js          ← 英文文案（客户门户）
layout/DefaultLayout.vue ← 侧边栏/顶栏菜单
```

## 5. 常见改法速查



### 5.1 改页面标题/菜单文字

1. 先看页面是否用了 `$t('...')` 国际化
2. 客户门户文案 → `frontend/customer_portal/src/i18n/en-US.js`
3. 运营后台文案 → 多数在 `.vue` 文件或 `frontend/client_portal/src/i18n/`（如有）



### 5.2 改 Onboarding 步骤名称（例：Finance → Financied Detailed）

**只改步骤条标题**，改一处即可：

文件：`[frontend/customer_portal/src/i18n/en-US.js](../frontend/customer_portal/src/i18n/en-US.js)`

```js
onboarding: {
  basic: 'Profile',
  finance: 'Financied Detailed',   // ← 改这里
  docs: 'Documents'
}
```

页面 `[OnboardingWizard.vue](../frontend/customer_portal/src/views/OnboardingWizard.vue)` 通过 `$t('onboarding.finance')` 引用，**无需改 .vue**。

**改第二步表单字段标签**（Bank Name / Branch Name / Account Name / Account No.）：

文件：`[frontend/customer_portal/src/views/OnboardingWizard.vue](../frontend/customer_portal/src/views/OnboardingWizard.vue)` 第 54–63 行，目前是硬编码 `label="Bank Name"` 等。建议后续迁到 `en-US.js` 统一管理。

**增删 bank 字段**（需前后端一起改）：


| 层    | 文件                                                                |
| ---- | ----------------------------------------------------------------- |
| 前端表单 | `frontend/customer_portal/src/views/OnboardingWizard.vue`         |
| 后端校验 | `apps/user_portal/serializers.py` → `OnboardingFinanceSerializer` |
| 数据库  | `apps/user_portal/models.py` → `UserOnboarding` + 新建 migration    |


**注意**：运营后台 `frontend/client_portal/src/utils/format.js` 里的 `ROLE_NAME.finance` 是**财务岗位角色名**，与 Onboarding 步骤无关。

### 5.3 改 Onboarding 后端逻辑


| 需求        | 文件                                                                    |
| --------- | --------------------------------------------------------------------- |
| 提交/保存资料   | `apps/user_portal/services.py` → `submit_onboarding()`                |
| 查询状态      | `apps/user_portal/services.py` → `get_onboarding()`                   |
| 运营审核      | `apps/user_portal/services.py` → `review_onboarding()`                |
| API 端点    | `apps/user_portal/views.py`、`urls.py`                                 |
| 审核通过后创建商户 | `apps/user_portal/services.py` → `_create_merchant_from_onboarding()` |




### 5.4 改订单/支付逻辑


| 需求   | 文件                                                |
| ---- | ------------------------------------------------- |
| 创建订单 | `apps/payment/services/payment.py`                |
| 退款   | `apps/payment/services/refund.py`                 |
| 汇款   | `apps/payment/services/remittance_application.py` |
| 关单   | `apps/payment/services/close_order.py`            |




### 5.5 改运营后台某页面

1. 在 `[frontend/client_portal/src/router/index.js](../frontend/client_portal/src/router/index.js)` 找到路由 → 对应的 `views/*.vue`
2. 看该页面 `import` 了哪个 `api/*.js`
3. 顺着 API 文件里的 URL 去 `apps/*/views.py` 找后端实现



### 5.6 新增一个 API 接口

1. `apps/<模块>/models.py` — 如需新表
2. `apps/<模块>/serializers.py` — 请求/响应格式
3. `apps/<模块>/services.py` — 业务逻辑
4. `apps/<模块>/views.py` — ViewSet 或 APIView
5. `apps/<模块>/urls.py` — 注册路由
6. `b2b_payment/urls.py` — 确认已 include（通常已挂载）
7. 前端 `api/*.js` + `views/*.vue` — 调用新接口

## 6. Onboarding 完整数据流

```
客户填写 OnboardingWizard.vue
        │
        ▼
POST /api/v1/user/onboarding/submit/
        │
        ▼
apps/user_portal/services.py → submit_onboarding()
        │  写入 UserOnboarding 表
        │  设置 EndUser.onboarding_status = pending
        ▼
运营在 KycReview.vue（/kyc）审核资料
        │
        ▼
POST /api/v1/admin/onboarding/{id}/review/
        │
        ▼
review_onboarding() → approved 时自动创建 Merchant + KYC
        │
        ▼
同一页继续 KYC 准入（费率/限额）
        │
        ▼
POST /api/v1/admin/merchants/{merchant_no}/review-kyc/
```

## 8. 快速定位口诀
