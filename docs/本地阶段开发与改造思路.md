## 2. 资金怎么走（本地）

**目标语义：**

```text
Customer 名下已有系统账面（入金用 Mock / 运营确认，不接银行）
        ↓
Agent 选一名下 Customer，提交转账请求
  （金额、币种、Customer 指定的收款方账户）
        ↓
CapitalPay 校验该 Customer 可用账面 + 合规
        ↓
Mock 付出 → 扣 Customer 账面 → 记「已拨付」
```

**现网大致：** 代客提交订单 → 运营同意/确认收款时贷记 Customer VA → Confirm transfer 再借记 Customer VA → Mock/运营付出。Agent 无自有可用账面；运营侧 `AgentDisbursement`（从 Agent 账户拨出）语义仍不对。

要点：

- 扣的是 **Customer 的钱**，打到 **Customer 指定的收款方**。
- Agent 只提交请求、代填信息，资金不进 Agent 口袋。
- 后续要把现网资金路径对齐到上面目标，或明确分阶段保留「贷记再借记」。



1. 资金路径：对齐「Customer 账面 → 付出」目标，理清与现网「先贷记再借记」的差异；弱化/改造 `AgentDisbursement`。
2. 补齐代客：入驻/KYC 代填、入金代办、订单补件/关单等，与 Customer 同一套服务 + 绑定校验。
3. 金额不符不要把 Mock 入金丢掉，进待处理；自动匹配不要用「金额+时间窗」。
4. 余额文案统一 System book balance（Customer Wallet 演示页等勿写成银行余额）。

## 5

1. **资金与记账对齐** — 明确本地用预存直扣还是保留贷记再借记；账与流水挂 Customer；处理 `AgentDisbursement`。
2. **代客补全** — 代填 KYC、代查/代管订单与入金；权限校验绑定关系。
3. **本地 Mock 闭环** — 运营模拟入金到 Customer 账面 → Agent 代提交转账 → Mock 付出；差额进待处理。
4. **种子数据** — Agent + 若干 Customer：有余额待转、已代提交、待审差额场景。
